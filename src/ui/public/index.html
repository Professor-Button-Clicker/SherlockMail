Overview

SherlockMail is a forensic email collection tool designed for legal, compliance, and investigative professionals. It connects to mail servers via IMAP, acquires emails with full cryptographic verification, maintains a tamper-evident chain of custody, and exports to industry-standard formats.

Forensic-Grade Hashing Every message is hashed with MD5 and SHA-256 at acquisition time. Hashes are stored and can be independently verified.
Chain of Custody Hash-chained audit trail (SHA-256) ensures any tampering with the log is detectable.
Multi-Format Export Export to EML, MBOX, XML, MSG, PST (deferred), and containerized formats.
QC Verification Post-acquisition reconnection to the mail server to verify counts and hashes match.

Getting Started

To begin using SherlockMail:

  1. Create a Project — Click the "+ New" tab and fill in the case details, target email, and examiner information.
  2. Start a Collection — Go to the "Collect" tab to launch the step-by-step collection wizard.
  3. Review Results — Browse collected data in the "Review" tab, view chain of custody in the "Tracker" tab, verify results in the "QC" tab.
  4. Export & Verify — Use the wizard's export and QC steps to produce court-ready output.
App Password Required

Most modern email providers (Gmail, Outlook, Yahoo) require an app-specific password for IMAP access. Enable 2FA on the target account and generate an app password in the provider's security settings.

Creating a Project

A project represents a single forensic collection matter. Each project has:

  • Project Name — Descriptive name for the collection
  • Target Email — The email address to collect from
  • Provider Type — IMAP (most common), Gmail API, Microsoft Graph, EWS, or POP3
  • Case Details — Case name, case/matter ID, examiner name, and agency

SherlockMail can auto-detect the email provider. Click "Detect Provider" after entering the target email to automatically configure IMAP settings.

Running a Collection (Wizard)

The collection wizard guides you through 9 steps:

  1. Connect — Enter IMAP credentials and test the connection
  2. Workflow — Select output formats, attachment collection options, and save location
  3. Query — Optionally filter by date range, sender, subject, or keywords
  4. Folders — Select which mail folders/labels to collect
  5. Preview — Review total items and settings before collection begins
  6. Collecting — Live progress display during acquisition
  7. Results — View completed collection stats, errors, and logs
  8. QC Verify — Re-verify collected data against the mail server
  9. Transfer — Copy collected data to another location (network drive, external storage)

QC Verification

QC verification reconnects to the mail server after acquisition and compares:

  • Folder message counts — Server count vs. collected count per folder
  • Message hashes — SHA-256 hash comparison of re-fetched messages against stored hashes
  • Message sizes — Size comparison per message
  • EML file integrity — Verifies stored EML files match their recorded hashes
Forensic Integrity Notice

SherlockMail never fabricates or creates false positive QC results. All verifications report honest results: PASS when all checks pass, or ISSUES_FOUND with detailed per-folder and per-message differences. This is a forensic tool — all collections must be verifiable in court.

Drive Link Attachments

SherlockMail detects cloud storage links embedded in email content from these providers:

  • Google Drive (drive.google.com, docs.google.com)
  • Microsoft OneDrive (onedrive.live.com, 1drv.ms)
  • SharePoint (*.sharepoint.com)
  • Dropbox (dropbox.com, dl.dropboxusercontent.com)
  • Box (box.com, app.box.com)
  • Apple iCloud (icloud.com)

Enable "Collect Drive Link Attachments" in the workflow step to detect and catalog these links during collection. After collection, you can create drive packages that bundle parent emails with their drive link metadata.

Chain of Custody

Every significant action is logged with a hash-chained audit trail:

  • Each entry includes a timestamp, event type, description, and examiner name
  • Each entry's hash = SHA-256(previousHash | timestamp | eventType | description)
  • The chain can be verified at any time — any modification to an entry breaks the chain
  • Events include: project creation, acquisition start/complete, message acquired/failed, searches, QC results, exports

Click "Verify Chain Integrity" in the Chain of Custody tab to validate the entire chain.

Security & Forensic Integrity

  • All credentials are transmitted only to the configured IMAP server — never stored in plain text in the database
  • TLS is enabled by default for all IMAP connections
  • App-specific passwords are recommended over primary account passwords
  • The database uses SQLite with WAL mode for crash-resistant writes
  • Hash verification uses cryptographic SHA-256 — collision-resistant for forensic purposes
  • All exports preserve original MIME source data — no modification of email content
  • QC verification provides honest, verifiable results — no false positives under any circumstances
